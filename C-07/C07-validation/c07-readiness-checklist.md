# C7-1 Naming Conventions

## Naming checklist

- [ ] My variables have clear, descriptive names.
- [ ] I do not use single-letter variable names except simple loop counters such as `i`.
- [ ] My constants use a consistent style, such as `UPPER_SNAKE_CASE`.
- [ ] My functions/methods use clear action names, such as `calculate_total` or `validate_input`.
- [ ] My classes use clear concept names, such as `StudentRecord` or `HabitTracker`.
- [ ] My interface controls use a consistent prefix system, such as `btn_`, `txt_`, `lbl_`, or `cmb_`.
- [ ] I completed `naming-conventions-declaration.md`.
- [ ] My actual code matches my declared conventions.

# C7-3 Validation Techniques

During validation, I will add validation checks to real inputs in my picked feature.

The three validation check types are:

- existence check — was something entered?
- type check — is it the right type of data?
- range check — is it within a sensible limit?

## Validation checklist

- [ ] I know which inputs in my project need validation.
- [ ] I can identify where an existence check is needed.
- [ ] I can identify where a type check is needed.
- [ ] I can identify where a range check is needed.
- [ ] I can label validation checks using `# C723`, `# C724`, and `# C725`.
- [ ] I can run a quick test to prove that a validation check works.
